## 1. Staged Clinical Rollout Protocol

Promotion between stages requires empirical evidence and signed clinical authorization. **Zero automatic promotion is permitted.**

```
[ STAGE 0: LOCAL & CI SANDBOX ]
  • Unit tests, math suites, and RBAC matrix passing 100%
  • Clean TypeScript build (tsc --noEmit = 0 errors)
  • DEMO_MODE only; synthetic fixtures clearly labelled
         │  Sign-off: Lead Architect, QA Lead
         ▼
[ STAGE 1: INTEGRATION SIMULATOR LAB ]
  • VirtualAnalyzerSimulator & TCP failure injection
  • ASTM E1381/E1394 malformed frames, NAK retry, and DLQ verification
  • Server restart and database disconnect recovery verification
         │  Sign-off: Integration Test Engineer, SRE
         ▼
[ STAGE 2: ISOLATED NON-PRODUCTION BENCH ]
  • Physical analyzer test ports (Sysmex, Roche, Abbott, Stago)
  • Non-patient QC materials and calibrators only
  • Verified bidirectional query, code mapping, and 24h soak stability
         │  Sign-off: Biomedical Engineer, Vendor Field Specialist
         ▼
[ STAGE 3: SHADOW OPERATION (MINIMUM 14 DAYS) ]
  • Mirror live hospital feed; zero writes to HIS or clinical reports
  • Parallel concordance audit against existing validated LIS
  • 100% agreement on specimen identification and critical panic flags
         │  Sign-off: Pathologist, Quality Manager (ISO 15189), Lab Director
         ▼
[ STAGE 4: SUPERVISED CLINICAL PILOT ]
  • Controlled single department (e.g. STAT Chemistry)
  • 100% manual pathologist sign-off on autoverified candidates
  • Daily backup restoration drills and audit integrity checks
         │  Sign-off: Chief Pathologist, CISO, Laboratory Director
         ▼
[ STAGE 5: CONTROLLED PRODUCTION ENABLEMENT ]
  • Formal IQ/OQ/PQ validation dossier signed per NABL 112
  • Feature-by-feature enablement via cryptographically signed policy
```

## 2. Database Migration & Rollback Runbook

### 2.1 Pre-Migration Backup Verification
```bash
# 1. Create timestamped custom-format PostgreSQL dump
export BACKUP_TS=$(date -u +"%Y%m%dT%H%M%SZ")
pg_dump --format=custom --no-owner --no-acl "$DATABASE_URL" > "/var/backups/labcore/pre_deploy_${BACKUP_TS}.dump"

# 2. Compute cryptographic SHA-256 integrity checksum
sha256sum "/var/backups/labcore/pre_deploy_${BACKUP_TS}.dump" > "/var/backups/labcore/pre_deploy_${BACKUP_TS}.dump.sha256"

# 3. Verify backup readability
pg_restore --list "/var/backups/labcore/pre_deploy_${BACKUP_TS}.dump" > /dev/null
echo "Pre-deployment backup verified: pre_deploy_${BACKUP_TS}.dump"
```

### 2.2 Forward Migration Execution
```bash
cd backend
npx prisma migrate deploy
```

### 2.3 Emergency Rollback Procedures

#### A. Emergency Operational Stop (< 10 seconds):
If unexpected behavior occurs in production:
1. Issue HTTP `POST /api/v1/nexus/emergency-stop` with Lab Director credentials, OR
2. Set environment variable `NEXUS_EMERGENCY_STOP=true` and restart Node.js runtime.
This immediately downgrades the platform to read-only `SHADOW_MODE` and halts all automated rerouting.

#### B. Application Version Rollback (< 2 minutes):
```bash
# Revert Docker container to previous pinned immutable image digest
docker compose -f docker-compose.prod.yml down
sed -i 's/IMAGE_TAG=latest/IMAGE_TAG=v2.5.0-verified/' .env.production
docker compose -f docker-compose.prod.yml up -d
```

#### C. Full Point-in-Time Database Restore:
```bash
pg_restore --clean --if-exists --no-owner -d "$DATABASE_URL" "/var/backups/labcore/pre_deploy_${BACKUP_TS}.dump"
```

## 3. Telemetry State & Monitoring Runbook

A production dashboard must never claim an instrument is healthy merely because its UI component renders. Every instrument interface reports one of 6 explicit states:

| Telemetry State | Diagnostic Definition | Visual Indicator | Operational Permission |
|---|---|---|---|
| **`LIVE`** | Verified ASTM/HL7 message or heartbeat received within 120 seconds. | Pulsing Emerald Badge | Live operations & autoverification allowed in `CONTROLLED_PRODUCTION_MODE`. |
| **`STALE`** | Socket connected, but no verified message received in > 120 seconds. | Amber Warning Badge | Autoverification locked; technician investigation alerted. |
| **`DISCONNECTED`**| TCP socket dropped, refused, or offline. | Solid Rose Badge | Instrument locked; manual bench mode or backup reroute triggered. |
| **`SIMULATED`** | Data generated by synthetic mathematical model or demo generator. | Violet Striped Badge | **HARD-BLOCKED from clinical production**; active in `DEMO_MODE` only. |
| **`DEGRADED`** | Interface active but experiencing $\ge 3$ consecutive NAKs or DLQ backlog. | Flashing Orange Badge | Technician triage required; autoverification suspended. |
| **`UNKNOWN`** | Initialization state prior to first verified handshake probe. | Slate Neutral Badge | Read-only observation. |
