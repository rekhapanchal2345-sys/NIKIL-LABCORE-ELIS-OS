## 2026-10-27 - [N+1 DB Query Optimization in backend/api/src/modules/approvals/approval.service.ts]
**Learning:** In the `batchApproveResults` function of the approvals service, there was an N+1 query issue where the remaining results for each order were queried sequentially inside a `for...of` loop using `await prisma.result.count()`. This can cause significant database performance bottlenecks, particularly when dealing with large batches. The optimization replaced this loop with a grouped `prisma.result.groupBy()` query and batch-updated via `prisma.$transaction([ ... updateMany() ])`.
**Action:** When inspecting Prisma code, actively look for loops over large sets that contain `await` and consider strategies like `.groupBy()`, `.findMany({ where: { in } })` and bulk updates such as `updateMany()` within transactions instead of executing queries in loops.
