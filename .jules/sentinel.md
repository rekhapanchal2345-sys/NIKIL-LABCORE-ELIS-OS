## 2025-02-28 - Hardcoded Fallback Secrets for Cryptographic Operations
**Vulnerability:** Found multiple instances where the application fell back to hardcoded strings (e.g., `'NIKIL-LABCORE-ELIS-OS-NABL-ISO15189-QR-SECRET-KEY-2026'`, `'aether-nexus-secret-key-2026'`, `'labcore-enterprise-aes256-default-key-32chars'`) for critical operations like HMAC generation and AES encryption if environment variables were missing.
**Learning:** Developers likely added these fallbacks to make local development easier or to prevent the application from crashing on startup if configuration was missing. However, this meant that if a production environment accidentally missed a variable, the application would silently use a known, publicly visible key for security operations, leading to critical vulnerabilities (e.g., forgeable digital signatures, decryptable backups).
**Prevention:** Always fail securely. Critical cryptographic operations should `throw new Error()` if required secrets are missing, rather than falling back to default, hardcoded, or easily guessable strings. Use configuration validation at startup to ensure all required secrets are present before accepting connections.
